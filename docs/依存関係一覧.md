# 依存関係一覧（インストールが必要なもの）

本システムを動かすために必要なものを、pipパッケージ・vLLMのモデル・自動取得モデル・
DB・環境変数の順にすべて挙げる。調査日: 2026-09-02（コード・`pip list` を実測）。
chromadb の除去とベクトルストアの置き換えに伴い 2026-09-06 に、推論を Ollama から vLLM へ
切り替えたのに伴い 2026-11-23 に更新（Ollama の記述は vLLM に置き換えた）。

依存の正は [requirements.txt](../requirements.txt)（バージョン固定）と本書（用途と使用箇所）である。
パッケージを追加・削除したら両方を更新すること。

## 3. vLLMで起動するモデル

| モデル（Hugging Face） | `--served-model-name` | 役割 | 必須度 |
| --- | --- | --- | --- |
| `BAAI/bge-m3` | `bge-m3` | **埋め込み**（1024次元。[ingest/embedder.py](../ingest/embedder.py) にハードコード） | 必須 |
| `openai/gpt-oss-120b`（Colabは `openai/gpt-oss-20b`） | `gpt-oss-120b`（Colabは `gpt-oss-20b`） | 回答生成 | 必須 |
| `Qwen/Qwen3-VL-30B-A3B-Instruct-FP8`（Colabは `Qwen/Qwen3-VL-8B-Instruct`） | `qwen3-vl-30b-a3b`（Colabは `qwen3-vl-8b`） | **VLM**。CLIは `--with-vlm`、画面からの取り込みは常に図表を説明文にする | VLM使用時 |

- 画面（[rag_web/app.py](../rag_web/app.py)）はモデルを選ばせず、生成モデルは環境変数 `VLLM_CHAT_MODEL` の1つで固定している。
- モデル名は環境変数 `VLLM_CHAT_MODEL` / `VLLM_EMBED_MODEL` / `VLLM_VLM_MODEL` で決まり、vLLMの `--served-model-name` と一致させる（[ingest/vllm_config.py](../ingest/vllm_config.py)）。
- 埋め込みモデルを変えると次元が変わり既存のベクトルが使えなくなる。DBには埋め込みモデルが記録され、
  設定と食い違うDBは開いた時点で止まる。差し替えるなら
  [ingest/embedder.py](../ingest/embedder.py) の `EMBED_DIM` を変更し、
  `vector_store.sqlite3` を削除して全ファイルを再取り込みすること。
- Ollama版で作ったDBをvLLMのbge-m3へ切り替えるときは、先に
  `python -m scripts.check_embedding_compat --db vector_store.sqlite3` で一致を確かめる。
- GB10のvLLMの起動指定とメモリ配分は [docs/server-deployment.md](server-deployment.md)。

## 5. DB

標準ライブラリの `sqlite3` に保存し、検索はnumpyの総当たりで行う。**pipパッケージもサーバも
追加不要**である。ChromaDBは2026-09-05に外した。HNSW索引が壊れても件数だけは正しく返り、
ベクトルの喪失が次回起動まで露見しなかったためで、経緯は
[設計書](superpowers/specs/2026-09-05-sqlite-vector-store-design.md) の2.1節にある。

- 保存先: `vector_store.sqlite3`（[ingest/store.py](../ingest/store.py) の `DB_FILENAME`）
- 距離: cosine。実装は [ingest/vector_store.py](../ingest/vector_store.py)
- BM25側は外部依存のない自前実装（[ingest/lexical.py](../ingest/lexical.py)）で、追加インストールは不要
- `chroma_db/` は残してあるが本システムはもう読み書きしない（ローカルの旧教材スクリプトが使い続ける）

**テーブルは2つある。** 同じ本文が複数の資料に現れるため、本文とベクトルは1つだけ持ち、
出現は資料ごとに持つ。

- `chunks(id, text, embedding)` — `id` は本文のSHA-256。本文とベクトルはここにしかない
- `occurrences(id, chunk_id, source, metadata)` — `id` は従来と同じ `source::location::index`。
  メタデータは資料固有なのですべてこちら

保存は出現単位、検索は本文単位である。`count()` は出現数、`chunk_count()` は本文の種類数を返す
（実データでは 608 出現 / 538 本文、2026-09-06 時点）。経緯と設計は
[設計書](superpowers/specs/2026-09-06-chunk-folding-design.md) にある。

1テーブル時代のDBは `open_store` が開かずに停止する。黙って書き換えると、移行が途中で
失敗したときに何が起きたか分からないDBだけが残るためである。変換はこの1行で、
再埋め込みは要らない（退避を取り、検証が通ってから元のファイルを置き換える）。

```
python -m scripts.migrate_store vector_store.sqlite3
```

## 6. 環境変数（`.env`）

`.env.example` を `.env` にコピーする。手元（`127.0.0.1`）のvLLMを既定の宛先のまま使うなら、`VLLM_*` は**すべて空のままで動く**
（ただしWeb UI `rag_web` を起動するときは `RAG_WEB_ADMIN_PASSWORD_HASH` だけは必須）。

| 変数 | 用途 |
| --- | --- |
| `VLLM_CHAT_URL` | 生成のvLLM（既定 `http://127.0.0.1:8001`）。`/v1` を付けない |
| `VLLM_EMBED_URL` | 埋め込みのvLLM（既定 `http://127.0.0.1:8002`） |
| `VLLM_VLM_URL` | 画像説明のvLLM（既定 `http://127.0.0.1:8003`） |
| `VLLM_CHAT_MODEL` | 生成のモデル名（既定 `gpt-oss-120b`） |
| `VLLM_EMBED_MODEL` | 埋め込みのモデル名（既定 `bge-m3`） |
| `VLLM_VLM_MODEL` | 画像説明のモデル名（既定 `qwen3-vl-30b-a3b`） |
| `VLLM_API_KEY` | vLLMの `--api-key`（Colab側のプロキシの認証キーも同じ形）。3つの宛先に `Authorization: Bearer` で送る |
| `OLLAMA_HOST` / `OLLAMA_API_KEY` / `OLLAMA_VLM_MODEL` | **廃止**。残っていると入口が「VLLM_* へ移行してください」と止める |
| `RAG_WEB_ADMIN_PASSWORD_HASH` | Web UI（`rag_web`）の管理者パスワードのハッシュ。**`rag_web` の起動に必須**（`python -m rag_web.password` で作る）。 |
| `RAG_WEB_HOST` | `rag_web` の待ち受けアドレス（既定 `127.0.0.1`） |
| `RAG_WEB_PORT` | `rag_web` の待ち受けポート（既定 `8502`。1〜65535） |
| `RAG_WEB_MAX_UPLOAD_MB` | `rag_web` で1回にアップロードできる合計サイズ（MB、既定 `50`） |
| `RAG_WEB_SESSION_TTL_HOURS` | `rag_web` の管理者ログインの有効時間（時間、既定 `12`） |
| `RAG_WEB_COOKIE_SECURE` | `rag_web` のログインCookieに `Secure` を付けるか（`true`/`false`、既定 `false`。HTTPSで公開するときは `true`） |
| `RAG_WEB_FORWARDED_ALLOW_IPS` | `X-Forwarded-For` を信じる前段（リバースプロキシ）の接続元。カンマ区切りで複数可（既定 `127.0.0.1`）。空にするとヘッダーを一切信頼しない。`*` と、IP アドレス・CIDR でない値は起動時に拒否する |
| `RAG_WEB_THREADPOOL_SIZE` | 同期ルートを走らせるスレッドプールの大きさ（1以上、既定 `40`） |
| `RAG_WEB_MAX_COWORK_JOBS` | 同時に走らせる Cowork（文書生成）の数（1以上、既定 `2`。超えた分は 503 で断る） |
